# E19 — Экран мира и конфиг

**Этап ТЗ:** 6. Стык с NeoForge и приёмка  
**Статус:** planned  
**Зависимости:** [E5](e5-world-style.md)  
**Следующий:** [E20](e20-acceptance.md)

После стиля. Параллельно с E6–E18, пока не трогает `MixinServerLevel`, кэш и `CubeStatusTasks`. Общий файл с E5 — `CommonConfig`: E5 уже записал смысл флага, здесь только экран и момент записи.

---

## Цель

На экране создания мира 26.1 есть переключатель кубических чанков. Он пишет `CommonConfig.generateNewWorldsAsCC`. Новый мир получает стиль по правилу E5. Конфиг не перезаписывается на диск на каждое мелкое чтение.

---

## Scope

- `MixinCreateWorldScreen` на фактическом экране 26.1.2.
- Строка локализации `selectWorld.cubicChunks` в `en_us.json`. Русская строка — если в ресурсах мода появится `ru_ru`, одной строкой; отдельную вычитку перевода не разворачивать.
- `CommonConfig.markDirty`: запись по выходу из экрана и по остановке игры, не на каждый `set`.
- `ServerConfig`: сообщение об ошибке при плохой строке стиля, без падения без текста. TODO «proper user feedback» закрывается этим.
- Вертикальная дистанция в том же toml остаётся ключом. Ползунок в GUI не обязателен.

---

## Out of scope

- Экран настроек внутри мира и команда смены стиля существующего мира. Стиль записанного мира не меняется (E5).
- Список измерений в GUI. Его правят файлом `serverconfig/cubicchunks.toml`.
- `EarlyConfig` диаметра в этом экране. Диаметр до первого мира, не кнопка.
- Перенос конфига на общий API «Forge/Fabric».

## Архитектура эпика

### Решение

Кнопка не пишет `worldStyle` напрямую. Она пишет общий флаг. E5 уже определил, как флаг становится стилем нового мира. Второй канал записи стиля с экрана запрещён.

### Состояние к концу E19

```text
CreateWorldScreen
└── переключатель, начальное значение из CommonConfig

CommonConfig
├── файл config/cubicchunks_common.toml
└── запись: выход с экрана и остановка клиента, не каждый set

ServerConfig
└── ошибка разбора стиля с именем ключа
```

Нет: GUI диаметра, GUI списка измерений.

### Поток экрана

1. Экран читает `shouldGenerateNewWorldsAsCC` при открытии.
2. Переключение меняет поле в памяти.
3. Уход с экрана или создание мира вызывает одну запись файла.
4. Создание мира идёт в E5: флаг → стиль нового уровня.
5. Уже существующий мир ту же кнопку не перечитывает как приказ сменить стиль.

### Модули

| Тема | Путь |
| --- | --- |
| Экран | `mixin/core/client/worldselection/MixinCreateWorldScreen.java` |
| Конфиг | `config/CommonConfig.java`, `config/BaseConfig.java`, `config/ServerConfig.java` |
| Строка | `src/main/resources/assets/cubicchunks/lang/en_us.json` |
| Стиль | не менять алгоритм E5, только вызвать его |

### Инварианты E19

1. Один `set` переключателя не обязан вызывать `write` файла. Создание мира обязано видеть уже выставленное значение.
2. Кнопка не затирает ключ стиля существующего мира.
3. Кривая строка в `ServerConfig` не становится молча `CUBIC`.
4. `EarlyConfig` этим эпиком не пишется.

## Критерии приёмки эпика

1. Экран создания мира показывает переключатель.
2. Выключенный переключатель даёт новый мир `CHUNK`. Включённый — `CUBIC`.
3. Повторный вход в старый мир не меняет его стиль из-за кнопки.
4. Битая строка стиля видна в логе и не молчит.
5. **Регрессия:** E5 алгоритм стиля, E4 меню, E8 вход в уже кубический мир.
6. **Документация:** ARCHITECTURE §2.

**Не требуется в E19:** смена диаметра, список измерений в GUI, русский перевод сверх одной строки.
