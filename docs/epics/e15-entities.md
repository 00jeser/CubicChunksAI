# E15 — Сущности

**Этап ТЗ:** 5. Играбельность  
**Статус:** planned  
**Зависимости:** [E8](e8-render.md)  
**Следующий:** [E16](e16-ticks-poi.md)

После видимого мира. Параллельно с E9–E14. Случайный тик уже в `cc_tickCube` (E6); E15 не включает `registerTickContainerInLevel` и не добавляет туда сущности — расписание остаётся E16. Общие файлы: `MixinEntity`, `MixinServerPlayer`, `MixinBlockCollisions`.

---

## Цель

Игрок и сущность сталкиваются с блоками куба, падают, переходят между кубами по Y и телепортируются на Y вне ванильной высоты, не выбрасываясь за мир.

---

## Scope

- `MixinEntity`: позиция куба, движение, телепорт.
- `MixinBlockCollisions`: выборка столкновений по кубам, а не по колонке фиксированной высоты.
- `EntityCubePosGetter`.
- `MixinServerPlayer`: телепорт. `findDimensionEntryPoint` и `changeDimension` — только если без них игрок гибнет на границе измерения; полная смена измерения не разрастается в отдельный сюжет.
- Трекинг сущности в `MixinChunkMap$TrackedEntity` по `CloPos`.

---

## Out of scope

- Спавн мобов — [E17](e17-spawn.md). Здесь сущность, уже существующая в мире.
- Тики блоков и жидкости — [E16](e16-ticks-poi.md).
- Лут, ИИ сверх ванильного.
- Сохранение сущности: ванильный путь игрока и региона сущностей. Если он режет Y, чинить обрезку, не новый формат.

## Продуктовая модель

| Ось | Носитель |
| --- | --- |
| Где сущность для симуляции | `CubePos` через `EntityCubePosGetter` |
| Где сущность для ванильного трекера, пока он колоночный | адаптер в `MixinChunkMap$TrackedEntity`, не второй список мобов |
| Столкновение | блоки кубов, которые пересекает AABB |

Сущность не «живёт в колонке» и отдельно «живёт в кубе».

## Архитектура эпика

### Решение

Позиция сущности — блок. Куб вычисляется `Coords.blockToCube`. Столкновение собирает кубы, пересечённые AABB, и не обходит все загруженные кубы мира.

### Состояние к концу E15

```text
Entity
└── cc_cubePos: CubePos          обновляется при смене куба

TrackedEntity
└── cloPos сущности

BlockCollisions
└── итератор по кубам AABB
```

Нет: своего списка мобов мимо ванильного.

### Поток движения

1. Сущность сдвигает блок.
2. Если `CubePos` сменился, трекер обновляет `CloPos`.
3. Столкновения читают `CubeAccess` тех кубов, которые пересекает AABB.
4. Телепорт на Y=10000 режет только предел упаковки `CloPos`, не ванильный max измерения.
5. На стиле `CHUNK` пути 2–4 не подменяют ваниль.

### Инварианты E15

1. AABB не сканирует кубы вне своих границ.
2. `CHUNK` использует ванильные столкновения.
3. Телепорт за предел упаковки `CloPos` отклоняется явно, а не молча ставит сущность в Y=0.
4. E15 не добавляет тик сущностей в `cc_tickCube`. Случайные тики блока и жидкости уже делает E6, расписание и block entity — E16.

## Критерии приёмки эпика

1. Игрок ходит по рельефу и не проваливается сквозь камень.
2. Падение с высоты наносит урон.
3. `/tp` на Y=10000 оставляет игрока на этой высоте, мир вокруг грузится (E6–E8).
4. **Регрессия:** E5 `CHUNK` столкновения ванильные, E11 сейв блока, рендер E8.
5. **Документация:** ARCHITECTURE §4 описывает позицию сущности так, как сделано.

**Не требуется в E15:** натуральный спавн, печки, POI.
