# E14 — Структуры

**Этап ТЗ:** 4. Ванильная генерация  
**Статус:** planned  
**Зависимости:** [E12](e12-noise-biomes.md)  
**Следующий:** [E13](e13-surface-features.md)

Сразу после шума и биомов, до поверхности и фич. Методы `generateStructureStarts`, `loadStructureStarts`, `generateStructureReferences`. Шум не переписывать.

---

## Цель

Ванильная структура может начаться в кубе и сослаться на соседний куб. После перезапуска старты читаются из NBT, а не генерируются заново.

---

## Scope

- Три метода `CubeStatusTasks`.
- Хранение стартов и ссылок на `ProtoCube` / `LevelCube`.
- Запись этих тегов в NBT, который ввёл E11. Если E11 ещё не влит в рабочую ветку агента, спринт 14.3 ждёт его, а не заводит второй файл сейва.
- Ссылки по `CloPos`, не по колонке без Y.

---

## Out of scope

- Новые структуры мода.
- Деревни и крепости как особые случаи сверх ванильного `StructureManager`.
- Фичи, которые только выглядят структурами (деревья) — [E13](e13-surface-features.md).
- `HYBRID`: ванильные старты колонки уже живут в ванильном пути. Кубовый метод на `HYBRID` не создаёт второй набор стартов.

---

## Архитектура эпика

### Решение

Старт привязан к кубу, в чьём объёме лежит опорный блок. Ссылка хранит `CloPos` целевого куба. Колонка `Integer.MAX_VALUE` в этой ссылке не используется.

### Состояние к концу E14

```text
ProtoCube / LevelCube
├── structure starts
└── references: CloPos → структуры

NBT куба
└── те же теги, если E11 уже пишет NBT
```

Нет: отдельного региона структур.

### Поток

1. `generateStructureStarts` спрашивает ванильный менеджер в границах куба.
2. `generateStructureReferences` записывает соседние кубы, которые структура задевает.
3. Сосед, которого нет в `StaticCache3D`, не подгружается синхронно с диска из этого шага.
4. `loadStructureStarts` читает теги NBT и не зовёт генератор.
5. Поверхность E13 и карверы видят уже записанные старты.

### Модули

| Тема | Путь |
| --- | --- |
| Шаги | `world/level/cube/status/CubeStatusTasks.java` |
| Куб | `world/level/cube/ProtoCube.java`, `LevelCube.java` |
| NBT | писатель из E11, `MixinChunkMap.cc_save` |
| Ориентир | `src_old/.../mixin/levelgen/common/structure` |

### Инварианты E14

1. На `CUBIC` три метода не `passThrough`.
2. На `HYBRID` и `CHUNK` кубовые методы старты не создают.
3. Ссылка не кодируется `ChunkPos` без Y.
4. Повторный вход не плодит второй старт поверх загруженного.

## Спринты

```text
S1 старты → S2 ссылки → S3 загрузка из NBT
```

S14.3 можно начинать только когда `cc_save` пишет NBT (E11). Раньше — метод `loadStructureStarts` покрыт тестом на буфере, без файла мира.

## Критерии приёмки эпика

1. В новом мире находится ванильная структура (тип зависит от сида; тест фиксирует сид).
2. Структура, разрезанная границей кубов, собирается ссылками с обеих сторон.
3. Перезапуск не двигает её и не дублирует.
4. **Регрессия:** E12 рельеф, E11 блок игрока, `HYBRID` без второго набора стартов.
5. **Документация:** ARCHITECTURE §3 называет шаги структур живыми.

**Не требуется в E14:** деревья и руда (E13), лут сундуков как отдельная задача сверх ванильного load.
