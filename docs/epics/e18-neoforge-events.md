# E18 — События NeoForge

**Этап ТЗ:** 6. Стык с NeoForge и приёмка  
**Статус:** planned  
**Зависимости:** [E16](e16-ticks-poi.md)  
**Следующий:** [E20](e20-acceptance.md)

После тиков. Source set `forge` и `ForgeSet` пересекаются с любым параллельным эпиком, который трогает `build.gradle` `neoForge.mods` или `GlobalSet`. Таких параллельных нет, если E19 не лезет в source set.

---

## Цель

Загрузка и выгрузка куба видны NeoForge как события с `CloPos`. Классы из `movetoforgesourcesetlater` лежат в source set `forge` и подключены к моду. Вложения `AttachmentType` на `LevelCube` не теряются при сохранении.

---

## Scope

- Перенос `CCEventHooks`, `CCCommonHooks`, `EventConstructorDelegates` в source set `forge`.
- Перенос `MixinGenerationChunkHolder_Forge`.
- `neoForge.mods` публикует source set `forge`, не только `main`. Комментарий `FIXME should be forge` закрывается.
- События загрузки, выгрузки, тика — те, что уже намечены TODO (P4) в `CCEventHooks`.
- Раскомментирование блока `FORGE START` в `LevelCube` и запись вложений в NBT E11.
- `ForgeSet` остаётся набором NeoForge-типов. Если условный DASM уже умеет не применять набор на отсутствующем загрузчике — вынести расширение из `GlobalSet`. Если не умеет — оставить `GlobalSet extends ForgeSet` и записать это в ARCHITECTURE §8 как оставшееся ограничение, без второго набора-дубля.

---

## Out of scope

- Fabric-совместимые события.
- Полный каталог событий NeoForge «на всякий случай». Только хуки, без которых чужой мод ломает куб при загрузке чанка: создание куба, выгрузка, тик.
- Свой bus мода.
- `invalidateCapabilities` — делается здесь, если метод ещё есть в 26.1.2 и без него вложения текут. Если метода нет, пункт закрывается сверкой, не пустым хуком.

## Продуктовая модель

| Событие | Когда | Не путать с |
| --- | --- | --- |
| Событие куба | `CloPos` куба, `LevelCube` | ванильным `ChunkEvent` колонки |
| Событие колонки в `CHUNK` | ванильное, мод не подменяет | событием куба |
| Вложение на кубе | `AttachmentHolder` куба | вложением на `Level` |

## Архитектура эпика

### Решение

Чужой мод получает событие куба там, где ваниль зовёт событие чанка. Подсовывать `ChunkPos` без Y запрещено. Колоночное событие в `CUBIC` не стреляет для блоков, которые лежат в кубе.

### Состояние к концу E18

```text
source set forge
├── CCEventHooks
├── CCCommonHooks
├── EventConstructorDelegates
└── MixinGenerationChunkHolder_Forge

LevelCube
└── AttachmentHolder          пишется в NBT

GlobalSet
└── ForgeSet как в ARCHITECTURE §8 после решения спринта 18.3
```

Нет: событий на каждый `setBlockState`.

### Поток

1. Куб доходит до `full`. Хук шлёт событие загрузки с `CubePos`.
2. `cc_tickCube` после игровой работы шлёт событие тика, если ваниль шлёт его на чанк.
3. Выгрузка шлёт событие до снятия расписания E16.
4. Вложения читаются и пишутся рядом с NBT куба.
5. `CHUNK` идёт ванильными событиями.

### Модули

| Тема | Путь |
| --- | --- |
| Хуки | `movetoforgesourcesetlater/CCEventHooks.java`, `CCCommonHooks.java`, `EventConstructorDelegates.java` |
| Миксин | `mixin/core/common/movetoforgesourcesetlater/MixinGenerationChunkHolder_Forge.java` |
| Набор | `mixin/dasmsets/ForgeSet.java`, `GlobalSet.java` |
| Вложения | `world/level/cube/LevelCube.java` |
| Сборка | `build.gradle`, блок `sourceSets.forge` и `neoForge.mods` |

### Инварианты E18

1. В кубическом измерении событие чанка не несёт потерянный Y.
2. Source set `forge` реально в мод-жарнике. Класс хука грузится.
3. Вложение переживает перезапуск вместе с блоком E11.
4. Префикс `cc_` на миксинах source set сохраняется.

## Критерии приёмки эпика

1. Game test ловит загрузку куба с верным `CubePos`.
2. Выгрузка приходит до того, как куб исчез из кэша.
3. Тестовое вложение на кубе читается после перезапуска.
4. **Регрессия:** E16 тики, E11 сейв блока, E5 `CHUNK` без кубового события.
5. **Документация:** ARCHITECTURE §1 и §8.

**Не требуется в E18:** полный паритет всех событий NeoForge, Fabric.
