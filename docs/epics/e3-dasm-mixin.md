# E3 — DASM и Mixin на 26.1

**Этап ТЗ:** 1. Порт собирается  
**Статус:** planned  
**Зависимости:** [E2](e2-core-headers.md)  
**Следующий:** [E4](e4-signature-port.md)

После того как ядро трансформируется. Исходники миксинов может чинить только E4; здесь — загрузчик, версии и генерация конфигов.

---

## Цель

`dasm-neoforge` и Mixin поднимаются на NeoForge `26.1.2.116`, конфиги `cubicchunks.mixins.*.json` и `cubicchunks.dasm.json` генерируются, плагин `ASMConfigPlugin` применяется. Версия `dasm` в репозитории — та, которая так сделала, а не заранее выдуманная.

---

## Scope

- Зависимости `io.github.notstirred:dasm` и `dasm-neoforge`.
- `mixinGen` / `dasmGen` на Java 25.
- Проверка, что аннотации `@Dasm`, `@TransformFromMethod`, `@AddMethodToSets` есть в выбранном API.
- `ASMConfigPlugin` как `configurationPlugin` конфига `core`.
- Ошибка `DasmFailedToApply` остаётся сигналом «трансформ не встал», не глотается.

---

## Out of scope

- Починка каждой сломанной сигнатуры ванили в миксине — [E4](e4-signature-port.md).
- Перенос `ForgeSet` в source set `forge` — [E18](e18-neoforge-events.md).
- Условное применение наборов «только на NeoForge» — тот же E18.
- Оптифайн-конфиги из `src_old`.

## Архитектура эпика

### Решение

Стартовая координата — текущая `3.2.0` (`compileOnly` api, `runtimeOnly` `jarJar` `dasm-neoforge`). Если резолв или компиляция аннотаций против 26.1.2 падает, спринт фиксирует следующую версию, у которой POM зависит от NeoForge ветки `26.1` и пакет аннотаций содержит те же типы, что уже импортирует мод. Версию не повышать «до последней» без этой проверки.

### Состояние к концу E3

```text
Зависимости
├── dasm api = dasm-neoforge = <записанная версия>
└── jarJar несёт ту же версию в рантайм

Конфиги (генерируются, не правятся руками)
├── cubicchunks.mixins.core.json      plugin ASMConfigPlugin, JAVA_25
├── cubicchunks.mixins.access.json
├── cubicchunks.mixins.forge.json     source set forge объявлен, в мод пока не включён
└── cubicchunks.dasm.json
```

Нет: зелёной компиляции всех миксинов. Список красных файлов — вход E4.

### Поток загрузки

1. `genAll` пишет json миксинов и dasm.
2. FML читает `[[mixins]]` и `[[dasm]]` из toml.
3. `ASMConfigPlugin.postApply` дописывает фабрики конструкторов, как сейчас.
4. Класс с `@Dasm` без применённого трансформа падает `DasmFailedToApply` при `<clinit>` (`CubePyramid.initCubePyramids`). Это остаётся.

### Модули

| Тема | Путь |
| --- | --- |
| Версии dasm | `build.gradle` |
| Генераторы | `build.gradle` блоки `mixinGen`, `dasmGen` |
| Плагин | `mixin/ASMConfigPlugin.java` |
| Наборы | `mixin/dasmsets/*.java` |
| Сигнал сбоя | `exception/DasmFailedToApply.java` |

### Инварианты E3

1. ARCHITECTURE §8: ручное тело вместо DASM здесь не добавляется.
2. Префикс `cc_` не ослабляется.
3. `GlobalSet extends ForgeSet` в этом эпике не перестраивается.
4. Конфиги json не коммитятся как ручные дубликаты генератора, если их по-прежнему создаёт `genAll` в `processResources`.

## Критерии приёмки эпика

1. `./gradlew genAll` успешен.
2. Версии `dasm` и `dasm-neoforge` одинаковы и записаны в `build.gradle`.
3. Наборы в `mixin/dasmsets` компилируются.
4. **Регрессия:** E2 тесты ядра остаются зелёными; `DasmFailedToApply` не удалён.
5. **Документация:** ARCHITECTURE §8 называет фактическую версию `dasm` одной строкой.

**Не требуется в E3:** клиент до меню, зелёный `compileJava` всего мода.
